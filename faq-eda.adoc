== 지연 시간 모니터링 및 분석

.FSx for ONTAP 파일 시스템과 연결된 링크가 필요한 이유는 무엇입니까?
기본 지연 시간 분석에서 구성 요소별 세부 정보를 보려면 링크가 필요합니다. 링크가 없더라도 지연 시간, IOPS 및 처리량 그래프는 볼 수 있지만 자세한 세부 정보는 볼 수 없습니다. 자세한 내용은 link:task-configure-latency-monitoring.html["EDA용 Workload Factory에서 지연 시간 모니터링 구성"]을(를) 참조하십시오.

.지연 시간 알림은 어떻게 트리거됩니까?
경고는 동일한 작업 유형(읽기 또는 쓰기)에 대해 지연 시간 임계값과 IOPS 임계값이 모두 초과되고, 두 조건이 선택된 전체 시간 범위 동안 지속될 때만 발생합니다. 두 조건을 모두 요구하면 시스템이 실제 워크로드를 처리하는 동안 높은 지연 시간이 발생하도록 보장하여 오경보를 줄일 수 있습니다. 자세한 내용은 link:learn-latency-monitoring.html["EDA용 Workload Factory의 지연 시간 모니터링에 대해 알아보십시오"]을(를) 참조하십시오.

.기본 분석과 CloudWatch 그래프에서 지연 시간 값이 다르게 나타나는 이유는 무엇일까요?
기본 분석에는 ONTAP QoS 지연 센터 메트릭이 사용되고 지연 시간 그래프에는 CloudWatch 데이터가 사용되며, 이 두 소스는 데이터를 다르게 수집하므로 약간의 차이가 예상됩니다. 근본 원인 파악 자체는 ONTAP QoS 데이터에 의존합니다. 자세한 내용은 link:learn-latency-monitoring.html["EDA용 Workload Factory의 지연 시간 모니터링에 대해 알아보십시오"]을(를) 참조하십시오.

.지연 이벤트에 대한 기본 분석과 AI 분석의 차이점은 무엇입니까?
기본 분석은 모든 지연 이벤트에 대해 자동으로 실행되며 ONTAP QoS 지연 센터 메트릭을 사용하여 FlexCache, 용량 풀, QoS 제한, 디스크, 데이터 또는 클러스터 등 속도 저하의 원인이 되는 구성 요소를 식별합니다. AI 분석은 선택 사항이며 잠재적인 근본 원인, 영향을 받는 EC2 클라이언트 목록, 두 가지 이상의 해결 단계 등 복잡한 데이터 또는 클러스터 문제에 대한 심층적인 조사를 제공합니다. 자세한 내용은 link:task-analyze-latency-issues.html["EDA용 Workload Factory에서 지연 시간 문제 분석"]을(를) 참조하십시오.

.지연 시간 이벤트에 대해 AI 분석을 실행할 수 없는 이유는 무엇입니까?
계정 관리자가 AI 기능을 비활성화했거나 NetApp에서 관리하는 AI 크레딧이 활성화되었지만 월별 예산이 소진된 경우 AI 분석을 사용할 수 없습니다. 두 경우 모두 메시지가 표시되며 AI 분석을 사용할 수 없습니다.

.이벤트 테이블에 표시되는 지연 이벤트는 총 몇 개입니까?
각 볼륨에 대해 가장 최근에 발생한 침해 사례만 표시되며, 동일한 볼륨에 대한 이전 침해 사례는 표시되지 않습니다. 총 최대 200개의 이벤트가 표시되며, 새로운 이벤트가 추가되면 이전 이벤트는 삭제됩니다.

.지연 현상에 대한 알림은 얼마나 자주 받게 되나요?
두 가지 알림 빈도 중에서 선택할 수 있습니다. *매일 알림*(권장)은 동일한 파일 시스템에 대해 24시간 후에 다시 알림을 보내고, *지연 시간 초과 시 알림*은 최대 20분마다 한 번씩 알림을 보냅니다. 알림은 볼륨 단위가 아닌 파일 시스템 단위로 전송되며, 영향을 받는 모든 볼륨이 하나의 알림으로 그룹화됩니다(이메일에 최대 10개의 볼륨이 표시됨). 자세한 내용은 link:task-configure-latency-monitoring.html["EDA용 Workload Factory에서 지연 시간 모니터링 구성"]을(를) 참조하십시오.

.계정 수준 및 볼륨 수준 지연 시간 임계값은 어떻게 상호 작용합니까?
EDA에서 설정한 지연 시간 임계값은 기본적으로 전체 계정에 적용됩니다. General Storage 워크로드에서 개별 볼륨 지연 시간 임계값을 설정할 수도 있으며, 해당 볼륨에 대해서는 볼륨 수준 설정이 우선 적용됩니다. EDA에서 계정 수준 임계값을 업데이트해도 기존 볼륨 수준 설정은 변경되지 않습니다. 자세한 내용은 link:task-configure-latency-monitoring.html["EDA용 Workload Factory에서 지연 시간 모니터링 구성"]을(를) 참조하십시오.

.지연 시간 임계값 구성을 저장할 수 없는 이유는 무엇입니까?
중요 이벤트 임계값은 경고 임계값보다 높게 설정해야 합니다. 중요 임계값을 경고 임계값보다 낮게 설정하면 시스템에 오류가 표시되며 구성을 저장할 수 없습니다.



[[dashboards]]
== 대시보드

.SSD 용량 및 처리량 관리에서 자동화, 권장, 없음 모드의 차이점은 무엇인가요?
*알림만(권장)*: Workload Factory는 사용량을 분석하고 변경 사항을 제안하지만, 적용 여부는 사용자가 직접 결정하므로 모든 제어 권한을 유지합니다. *자동화*: Workload Factory는 구성된 조건이 충족되면 용량 또는 처리량을 자동으로 변경하므로 수동 작업이 필요하지 않습니다. *없음*: 시스템에서 권장 사항이나 자동화된 작업을 수행하지 않으므로 용량 관리는 사용자가 직접 해야 합니다. 자세한 내용은 link:learn-overview-dashboard.html["Workload Factory for EDA의 개요 대시보드에 대해 알아보십시오"]을(를) 참조하십시오.

.프로젝트 대시보드에서 사용자 지정 필터를 몇 개까지 생성할 수 있으며, 누가 이를 관리할 수 있습니까?
AWS 태그를 기반으로 최대 5개의 사용자 지정 필터를 구성할 수 있으며, 각 필터에는 필터 레이블, AWS 태그 키 이름 및 선택 유형(단일 또는 다중 선택)을 지정할 수 있습니다. Projects 대시보드를 여는 첫 번째 관리자만 사용자 지정 필터를 생성, 변경 또는 삭제할 수 있으며, 다른 관리자를 포함한 다른 모든 사용자는 필터를 보기만 할 수 있습니다. 자세한 내용은 link:task-configure-project-dashboard.html["Workload Factory에서 EDA용 프로젝트 대시보드 구성"]을(를) 참조하십시오.

.프로젝트 대시보드에서 사용자 지정 필터를 구성하지 않으면 어떻게 됩니까?
사용자 지정 필터를 구성하지 않으면 기본 필터(파일 시스템, 볼륨 유형 및 시간 범위)가 계속 사용 가능하므로 대시보드를 계속 보고 사용할 수 있습니다. 자세한 내용은 link:learn-project-dashboard.html["Workload Factory for EDA의 프로젝트 대시보드에 대해 알아보십시오"]을(를) 참조하십시오.

.프로젝트 대시보드의 볼륨 보기에는 몇 개의 볼륨이 표시됩니까?
볼륨 보기에는 각 메트릭(사용 용량, IOPS, 처리량)별로 상위 10개 볼륨만 표시됩니다. 볼륨이 10개가 넘는 경우 일부 볼륨은 상세 보기에 표시되지 않습니다. 자세한 내용은 link:learn-project-dashboard.html["Workload Factory for EDA의 프로젝트 대시보드에 대해 알아보십시오"]을(를) 참조하십시오.

== CI/CD 및 Perforce 통합

.EDA CI/CD에서 프로젝트와 워크스페이스란 무엇인가요?
프로젝트에는 소프트웨어 환경과 아티팩트를 나타내는 볼륨이 할당됩니다. 소프트웨어를 업데이트할 때 볼륨의 스냅샷을 생성하여 알려진 버전을 표시합니다. 개발, QA 또는 빌드 프로세스에 사용되는 특정 소프트웨어 버전의 복제본을 워크스페이스라고 합니다. 자세한 내용은 link:learn-eda-workloads.html["Workload Factory for EDA에서 Perforce 통합에 대해 알아보십시오"]을(를) 참조하십시오.

.프로젝트를 삭제하면 스냅샷과 클론은 어떻게 되나요?
프로젝트를 삭제하면 해당 프로젝트와 관련된 모든 코드 또는 아티팩트가 볼륨에서 삭제됩니다. 그러나 프로젝트의 스냅샷과 클론은 유지됩니다. 자세한 내용은 link:manage-projects.html["Workload Factory for EDA에서 EDA 프로젝트 관리"]을(를) 참조하십시오.

.프로젝트 복제에 어떤 제한을 설정할 수 있나요?
프로젝트를 생성할 때 최대 보존 기간(일, 이 기간이 지나면 Workload Factory에서 클론을 삭제함), 사용자 또는 그룹별 최대 클론 수, 최대 클론 크기(GiB) 등 운영 정책을 구성할 수 있습니다. 자세한 내용은 link:manage-projects.html["Workload Factory for EDA에서 EDA 프로젝트 관리"]을(를) 참조하십시오.

.Perforce와 Workload Factory for EDA를 어떻게 통합하나요?
P4V 통합 파일을 다운로드하고, P4V를 실행한 다음 *툴* > *툴 관리* > *HTML 탭*으로 이동하여 *HTML 탭 가져오기*를 선택하고, 통합 XML 파일을 선택한 후 *보기* > *Workload Factory*로 이동합니다. 그러면 EDA용 Workload Factory 웹 UI가 P4V 클라이언트 내에 HTML 탭으로 나타납니다. 자세한 내용은 link:integrate-perforce.html["EDA용 Workload Factory를 Perforce와 통합"]를 참조하십시오.

.Codebox란 무엇이며, EDA 워크로드 자동화에 어떻게 도움이 되나요?
Codebox는 Workload Factory에 내장된 IaC(Infrastructure-as-Code) 코파일럿으로, Workload Factory에서 지원하는 모든 작업을 실행하는 코드를 생성하는 데 도움을 줍니다. 리소스 생성 시 코드 스니펫 생성을 제공하고, 개발자 및 DevOps를 위한 IaC 코파일럿 역할을 하며, 빠른 재사용을 위한 코드 뷰어 및 자동화 카탈로그를 제공합니다. 자세한 내용은 link:automate-codebox.html["Codebox를 사용하여 EDA 워크로드 자동화"]을(를) 참조하십시오.

== 지원

.FSx for ONTAP과 Workload Factory 자체에 대한 지원은 누가 제공합니까?
Amazon FSx for NetApp ONTAP은 AWS 자체 솔루션이므로 지원을 받으려면 AWS Management Console의 지원 센터를 사용하여 "FSx for ONTAP"을 선택해 케이스를 여십시오. Workload Factory 또는 해당 애플리케이션 및 서비스에 대한 일반적인 질문은 link:get-help-eda.html["EDA 관련 도움 받기"]을 참조하십시오.
